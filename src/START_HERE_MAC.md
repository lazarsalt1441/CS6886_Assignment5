# Apple M1 native benchmark package

Your hardware: MacBookAir10,1, Apple M1, 4 performance + 4 efficiency cores,
8 physical / 8 logical cores, 16 GB unified memory.

The new online kernels include an explicit AArch64 NEON fast path. The archived
native run predates this optimisation. The current `report.pdf` is the owner's
uploaded replacement; collect a fresh result ZIP before updating its speed claims.

## Run

1. Unzip the download and open Terminal in its `attention_assignment` directory.
2. If Homebrew is not installed, install it from <https://brew.sh>.
3. Install the compiler, OpenMP runtime, and Python once:

   ```sh
   brew install llvm libomp python
   ```

4. Run the complete collection:

   ```sh
   bash src/run_macos.sh --tune --compare-legacy --profile
   ```

5. Upload the generated **Mac_Results.zip** from the assignment directory.

The runner prints progress. Allow several minutes; keep the laptop plugged in
and close heavy applications. It uses the CPU and needs no GPU or Python packages.
It keeps the Mac awake while the command runs, without changing system settings.
It does not need sudo or change global compiler/Python settings.

## What it does

- Compiles all six variants with Homebrew LLVM, `-O3 -mcpu=apple-m1`, and
  SIMD support. Only the OpenMP variant enables parallel OpenMP regions.
- Preserves every starter driver and the official inputs unchanged.
- Runs one warm-up plus the driver's five timed calls per invocation, and takes
  the median of three independent invocations per configuration.
- Sweeps OpenMP at 1, 2, 4, 6 and 8 threads.
- Checks each thread configuration against the naive result at the required
  `1e-4` relative-max tolerance; missing, truncated and non-finite outputs fail.
- Checks SIMD tails, uniform logits, and large logits against independent FP64
  attention implemented with Python's standard library.
- Adds boundary cases at 127/128/129 and multiple key tiles, plus early/late
  maximum changes and constant/zero values: 168 FP64 checks in total.
- Measures ten cache/register tile configurations in two reversed-order rounds
  and applies the selected flags to both `best` and `omp`. `fused` uses 48x128
  cache tiles and four register rows. The local choice is retained in
  `output/kernel_config.mk` for subsequent Makefile builds.
- With `--compare-legacy`, runs previous and new fused/best kernels in alternating
  order. With `--profile`, collects separate single-thread packing, matrix-product
  and softmax timings. Profiling overhead is not mixed into `results.csv`.
- Measures sustained memory bandwidth with a 384 MiB triad, and achieved FP32
  FMA throughput with an independent NEON microbenchmark.
- Collects allowlisted hardware/cache information, compiler version, commands,
  source/input hashes, raw driver timings, and validation results. Serial numbers
  and hardware UUIDs are not included.

## Scheduling and peak calculations

macOS controls placement across P/E cores. No Linux CPU affinity mechanism is
used or emulated, and no P-core pinning is claimed. OpenMP query blocks use
`schedule(dynamic,1)` so faster workers can take more blocks.

Do not estimate M1 all-core throughput by multiplying one P-core peak by eight.
P/E cores differ. The FMA microbenchmark measures achieved throughput, not
theoretical architectural peak or a guaranteed P-core frequency. Unexposed
clock fields remain unavailable until supported by a separate source or probe.

## Other commands

```sh
make all
make check
make edge-check
```

`make all` is the starter-style run. The full result ZIP is generated by
`bash src/run_macos.sh`, which also collects bandwidth and hardware evidence.

On Linux, generic C/AVX-512 paths can be built with `make CC=gcc`; those runs
are correctness/development checks and are not M1 performance measurements.
